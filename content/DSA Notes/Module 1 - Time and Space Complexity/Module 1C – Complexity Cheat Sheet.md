
# Complexity Ladder

```text
🥇 O(1)

🥈 O(log N)

🥉 O(N)

🙂 O(N log N)

😬 O(N²)

😱 O(N³)

💀 O(2ᴺ)

☠️ O(N!)
```

---

# Interview Verdict

| Complexity | Verdict                     |
| ---------- | --------------------------- |
| O(1)       | Amazing                     |
| O(log N)   | Amazing                     |
| O(N)       | Excellent                   |
| O(N log N) | Usually Optimal             |
| O(N²)      | Acceptable for Small Inputs |
| O(N³)      | Usually Too Slow            |
| O(2ᴺ)      | Dangerous                   |
| O(N!)      | Apocalypse                  |

# Five Questions to Ask Every Algorithm

```text
1. Is it correct?

2. What is its Time Complexity?

3. What is its Space Complexity?

4. Can I reduce repeated work?

5. Can I trade memory for speed?
```

---

> [!Note]  
> If you can confidently answer those five questions for any solution, you have mastered the foundation upon which every major DSA topic is built. The rest of DSA is largely learning new data structures and recognizing patterns that improve those answers.
